# P2 多学校、多实例与 Redis 上线检查

- 日期：2026-11-09
- 状态：代码、临时双实例和双学校数据面已实测通过；生产基础设施配置与真实试点材料仍待学校环境签核

## 已具备的代码基础

### 多学校/数据面

- `SCHOOL_DATABASE_URLS` 支持学校 ID 到独立数据库 URL 的映射。
- `school_context` 负责解析当前学校和用户的数据范围。
- 工具调用携带 `school_id`，学生查询仍需超级管理员权限。

### Redis

- `REDIS_ENABLED` 控制共享缓存开关。
- 已存在 Redis 客户端、缓存版本、失效和运行时指标模块。
- 本地开发默认关闭，原因是当前没有独立 Redis 实例。

### 模型与回退

- 本地 3B 模型可独立部署为 llama-server。
- 模型端点失效时，规划器在超时后回退规则计划。
- 双计划默认关闭，避免未经验证的额外延迟。

## 上线前必须验证

1. 每所学校准备独立数据库账号，不使用同一个写权限账号。
2. 验证 `school_id` 与数据库 URL 的映射不存在默认回退越权。
3. 使用两个学校做交叉查询，确认不能读到另一学校数据。
4. Redis 开启后验证相同请求的缓存命中、数据变更后的版本失效和跨实例共享。
5. 后端至少启动两个实例，验证 Redis 共享缓存和会话一致性。
6. 模型升级采用“健康检查 → 小流量 → 全量”的顺序。
7. 模型回滚只切换配置和端点，不覆盖已生成报告或审计记录。
8. 对失败模型端点、超时、半开和恢复进行演练。

## 真实试点数据模板

至少记录：

- 试点学校数量和数据年份
- 每日活跃招生人员数量
- 单次查询完成时间中位数
- 人工核对次数和发现错误数
- 报告生成次数和导出次数
- 用户反馈分类
- 数据导入失败率
- 安全/权限事件数
