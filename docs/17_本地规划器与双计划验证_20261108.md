## 一、规划器接入

前端仍使用规则/ONNX 路由。复杂问题在规则计划之外调用本地规划模型：

```text
问题
→ 规则/ONNX 路由
→ 本地模型受控工具计划
→ 规则计划
→ 两个候选规范化比较
→ 一致性门控
```

本地规划器提示词包含：

- 当前识别意图
- 允许工具列表
- 每个工具允许的参数
- 结构化 JSON 输出格式
- 禁止学生档案和学生统计工具
- 禁止编造业务数字

配置：

```ini
MINIMIND_ENABLED=true
MINIMIND_BASE_URL=http://host.docker.internal:11434/v1
MINIMIND_MODEL=qwen2.5-coder-3b
MINIMIND_TIMEOUT_SECONDS=30
AGENT_CHAT_TIMEOUT_SECONDS=75
AGENT_PLAN_CONSISTENCY_THRESHOLD=1.0
```

## 二、触发策略修正

## 五、高风险双计划探针

测试 8 个高风险问题，包括预测、计划沙盘、跨年趋势和多指标综合分析。

| 指标 | 结果 |
|---|---:|
| 本地模型计划数 | 5 |
| 独立双计划触发数 | 1 |
| 双计划一致数 | 0 |
| 最终回答数 | 5 |
| 被门控拦截数 | 3 |
| P50 | 9735.30 ms |
| 最大延迟 | 11572.47 ms |

触发案例：

```text
预测2026年土木工程招生计划和录取情况，并分析历史趋势
```

结果：

- 本地模型计划：`admissions_overview`
- 规则计划：`forecast`
- 两个计划可以独立执行
- 结果相似度：`0.0`
- `τ_A=1.0`
- 最终策略：`insufficient_data`
- `can_answer=false`

这验证了：

1. 双计划不是同计划重复执行。
2. 只有候选签名不同才触发一致性比较。
3. 结果不一致时会停止回答，而不是强行拼接。

## 六、运行时影响

本地模型仅用于规划，不替代确定性工具。最终业务数字仍来自 MySQL 工具。

延迟影响：

- 简单问题仍走毫秒级规则路径。
- 使用本地模型的问题约 9—12 秒。
- 本地规划器不适合所有问题全量启用。
- 复杂预测与沙盘的延迟必须在比赛演示脚本中提前说明。

## 八、当前不足

- 高风险探针样本只有 8 题，不是正式准确率测试集。
