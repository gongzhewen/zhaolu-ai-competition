# G0 同类算法与产品对照

- 建立日期：2026-11-06
- 用途：说明拟议的“证据约束选择性多规划问数”与已有研究、产品和组件的相似性，划定创新主张边界。
- 注意：本文是内部研发记录，不是正式查新报告。投稿或答辩前应再次核对最新官方产品文档、论文和专利。

## 一、结论先行

市面和研究界已经分别存在以下能力：

- 自然语言数据分析
- 语义层和指标层
- 多候选推理与投票
- 语义不确定性估计
- 选择性分类与拒答
- 共形预测和风险校准
- 检索增强生成
- 工具调用智能体
- Text-to-SQL 验证和 SQL 修复

因此不能宣称“第一次提出多候选、拒答、RAG 或工具调用”。

本项目可争取的创新定位是：

> 针对高校招生敏感结构化数据，把招生语义约束、多计划结果一致性、数字级证据验证、风险预算门控和本地隐私边界组合成一套可执行的场景方法，并通过授权真实数据冻结测试集和消融实验证明增益。

这是应用算法和系统方法创新，不是新的基础数学理论。

## 二、相近研究与方法

| 方向 | 已有方法 | 与本项目相似处 | 本项目应有差异 |
|---|---|---|---|
| 多路径一致性 | Self-Consistency，多推理路径投票 | 都使用多个候选降低单次错误 | 本项目比较对象是结构化工具计划和规范化查询结果，不是自然语言答案投票 |
| 语义不确定性 | Semantic Entropy，对语义等价答案聚类后估计不确定性 | 都关注表述变化背后的语义歧义 | 本项目在年份、指标、专业、筛选条件等业务槽位上计算歧义，并直接触发澄清 |
| 选择性预测 | Selective Classification，允许模型在低置信度时拒答 | 都追求覆盖率与错误率平衡 | 本项目把业务硬约束、数据支撑、隐私风险和工具证据纳入门控 |
| 风险校准 | Conformal Prediction / Conformal Risk Control | 都使用校准集选择阈值并控制风险 | 本项目需验证在招生数据分布漂移和多工具计划下是否有效；不得声称共形保证自动成立 |
| RAG | Retrieval-Augmented Generation | 都使用外部知识补充语言理解 | 本项目 RAG只负责知识与语义辅助，关键数字仍由确定性工具产生 |
| 工具智能体 | ReAct、Toolformer 及现代 Agent 框架 | 都让模型选择工具和参数 | 本项目限制工具白名单、参数范围、数据权限，并验证执行证据 |
| 自然语言分析 | 企业 BI Copilot、Text-to-SQL 和语义层产品 | 都支持业务人员用自然语言查询数据 | 本项目聚焦招生领域口径、专业别名、敏感数据本地化和证据可审计性 |
| SQL 校验 | SQL 修复、结果校验和执行反馈 | 都会检查查询是否可执行或结果是否合理 | 本项目强调多计划结果一致性、业务语义证据和回答级风险门控 |

## 三、相近产品类别

以下是能力相近的产品类别，不代表它们与招录智策完全相同：

- Snowflake Cortex Analyst：企业语义模型和自然语言分析方向相近。
- Databricks AI/BI Genie：面向数据仓库的自然语言分析和智能问数方向相近。
- Microsoft Power BI Copilot / Microsoft Fabric：固定报表体系上的自然语言分析和辅助洞察方向相近。
- Google Looker 对话式分析：语义模型与自然语言数据查询方向相近。
- ThoughtSpot：自然语言搜索分析和智能洞察方向相近。
- 国内 BI 智能问数产品：FineChatBI、Quick BI 智能问数等同类方向，具体能力需以最新官方文档核验。
- 高校招生业务系统厂商：具有招生业务数据基础，但通常以流程管理和固定报表为主。

这些产品说明“自然语言问数”不是空白市场。招录智策不能用“别人没有聊天问数”作为创新点。

## 四、可能形成的差异化

### 1. 问题定义的差异化

把高校招生问数定义为：

> 在隐私不泄露、数据有证据、错误风险受控的条件下，最大化可正确回答的问题覆盖率。

其目标不是单纯提高回答率，而是控制高风险错误。

### 2. 算法机制的差异化

拟形成：

```text
槽位级语义歧义估计
→ 招生硬约束过滤
→ 单计划或自适应双计划
→ 受控工具与数据库执行
→ 数字级证据证书
→ 规范化结果一致性比较
→ 风险校准门控
→ 回答、澄清或拒答
```

其中单个组件多数已有先例，组合方式和招生业务约束需要由实验证明有效。

### 3. 数据和部署的差异化

- 授权真实招生数据的离线冻结评测
- 公开演示数据与真实评测数据严格分离
- 本地模型、本地数据库、本地知识库
- 外部网络断开后核心问数仍可运行
- 字段权限、敏感操作审计和隐私边界

部署安全本身不是算法创新，但它可以证明算法适合真实高敏感场景。

## 五、创新主张的红线和推荐写法

不要写：

- “行业首个”
- “原创全新算法”
- “首次提出语义熵/共形预测/多智能体一致性”
- “意图准确率 99.48%，所以回答准确率 99.48%”
- “真实高校试点已证明”，除非具有正式试点材料和学校许可

推荐写：

> 针对通用问数方法在招生计划、录取、报到等业务口径上易发生约束遗漏、指标混用和无依据回答的问题，本作品设计一种面向招生场景的证据约束选择性多规划方法。该方法在已有语义不确定性、受控工具调用和选择性回答思想基础上，引入招生槽位约束、多计划结果一致性和数字证据门控，并在本地部署和授权真实数据冻结测试集上开展消融验证。

## 六、必须完成的证明链

1. 用同一本地模型、同一数据库和同一硬件搭建通用强基线。
2. 建立冻结测试集，最新完整年度作为测试留出。
3. 对问题类别、标准答案和失败类型进行人工复核。
4. 比较最终答案准确率、无依据回答率、覆盖率、误拒答率和 P95 延迟。
5. 逐项做消融，证明每个新增模块有实际增益。
6. 报告置信区间，不用单一百分比代表整体能力。
7. 保存完整实验配置和可复现脚本。
8. 在正式材料中避免“第一”“原创”等未经查新的措辞。

## 八、最终判断

市面上存在大量相似组件和相近产品，但“高校招生领域的证据约束、多计划一致性、风险门控和本地私有化”作为一个完整方法仍有形成场景创新的空间。

能否在国赛中成立，不取决于概念名字，而取决于三件事：

1. 是否真的实现并接入现有产品链路；
2. 是否在授权真实数据冻结测试集上优于强基线；
3. 是否能通过消融实验证明增益来自算法机制，而不是数据、模型规模或实验条件差异。
