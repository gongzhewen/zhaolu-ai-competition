## 二、系统总体架构

### 2.1 技术栈

- 前端：React 19、TypeScript、Vite、Ant Design、ECharts、TanStack Query、React Router。
- 后端：FastAPI、Pydantic v2、SQLAlchemy Async。
- 数据库：MySQL 8；代码同时保留 PostgreSQL 兼容层。
- 缓存：进程内 L1；可选 Redis L2。
- 部署：Docker Compose、Nginx、宝塔面板、可选双后端实例。
- 本地知识：中文 BAAI BGE Embedding、政策 FAQ、DBF 数据字典、指标口径和安全原则。
- 本地规划模型：通过 OpenAI 兼容接口接入的 Qwen/MiniMind 类模型。
- 意图模型：PaddleNLP 训练 ERNIE Nano，导出 ONNX 后由 ONNX Runtime CPU 推理。
- 报告：`python-docx` 生成 Word，`reportlab` 生成 PDF。
- 导入：Excel、CSV、XLS、DBF-ZIP。

### 2.2 请求主链路

```text
用户问题
→ 最近 6 轮上下文归一化
→ 指代与省略表达解析
→ 学校上下文与权限范围确认
→ 中文口语归一化
→ 规则路由
→ ONNX 意图有限修正
→ 语义槽位编译
→ 歧义与槽位熵估计
→ 隐私/权限/注入/越界硬门控
→ 确定性多工具协调或单工具规划
→ 可选本地模型受控规划
→ 工具参数白名单传播
→ L1/L2 缓存检查
→ 受控工具执行
→ 数字级证据证书
→ 数字主张核验
→ 五维自查与数据支撑评分
→ 反思记忆规则复核
→ 风险评分与回答策略门控
→ 确定性回答 + 表格 + 图表 + 引用
→ 反馈、记忆、评测和运行指标落库
```

### 2.3 核心设计原则

1. 大模型不直接生产招生统计数字。
2. 业务数字必须来自受控数据库工具。
3. 模型只能建议工具和参数，且必须经过白名单、权限和范围校验。
4. 回答前必须检查证据、数字一致性、权限和风险。
5. 条件不清优先澄清；无数据明确说无数据；越权直接拒绝。
6. 真实敏感数据不进入公开源码包。
7. 没有实验证明收益的模块不得包装成“性能提升”。

### 3.6 槽位熵与语义不确定性

实现文件：

```text
packages/agent_core/agent_core/formal.py
```

单槽位熵：

```text
H_s = -Σ p_j log(p_j)
```

归一化熵：

```text
H̃_s = H_s / log(n_s), n_s > 1
H̃_s = 0, n_s <= 1
```

加权不确定性：

```text
U_sem = Σ w_s × H̃_s
```

默认权重：

| 槽位 | 权重 |
|---|---:|
| 指标 | 0.30 |
| 年度 | 0.15 |
| 专业 | 0.20 |
| 学生身份 | 0.20 |
| 省份 | 0.10 |
| 其他 | 0.05 |

实际歧义风险：

```text
risk_ambiguity = max(规则歧义, min(0.65, 0.5 × U_sem))
```

### 3.7 歧义识别与主动澄清

当前明确识别：

- “招生人数”可能是计划数或录取数。
- “招生规模”可能是计划规模或实际录取规模。
- “到校比例/报到比例”可能是报到率、未报到率或计划完成率。
- “这个专业怎么样”缺少标准专业和指标。
- “张性同学”可能是姓氏或姓名中包含这段文字。
- “某位/同名学生”无法唯一识别。
- 计划沙盘缺少专业或调整人数。
- 决策问题同时涉及过多指标时要求约束口径。

高风险歧义进入 `clarify`，不会猜测答案。

### 3.14 结果一致性相似度

规范化后计算：

```text
A(q) = Sim(R1, R2)
```

相似度组成：

- 指标数值相似度。
- 表格列集合 Jaccard。
- 表格行集合 Jaccard。
- 数据源集合 Jaccard。
- 工具覆盖率。
- 结果覆盖率。

默认：

```text
τ_A = 1.0
```

低于阈值时风险门控会拒绝把结果包装成确定答案。

### 3.18 数据支撑度

实现文件：

```text
packages/agent_core/agent_core/evaluation.py
```

基础分：

```text
0.7 × 自查分 + 0.3 × 路由置信度映射分
```

存在以下情况时施加上限：

- 未调用确定性数据工具。
- 缺少可追溯数据来源。
- 工具没有返回可验证指标。
- 证据证书不完整。
- 回答数字未被证据完全覆盖。
- 政策结论缺少知识依据。

默认充分阈值：

```text

```

### 3.19 风险评分

实现文件：

```text
packages/agent_core/agent_core/risk.py
```

风险公式：

```text
risk =
0.24 × 槽位歧义
+ 0.22 × 证据缺口
+ 0.20 × 数字缺口
+ 0.12 × 计划一致性缺口
+ 0.08 × 路由置信度缺口
+ 0.10 × 数据支撑缺口
+ 0.04 × 隐私风险
```

工具未返回可验证指标时：

```text
risk >= 0.82
```

默认回答阈值：

```text
0.32
```

否则按优先级返回：

- `no_permission`


### 4.5 否定反馈与二次复核

实现文件：

```text
packages/agent_core/agent_core/reflection.py
apps/api/app/modules/agent_intelligence/feedback_learning.py
```

流程：

1. 用户在回答下点击“否定”。
2. 记录原问题、原回答、意图、工具和用户原因。
3. 推断错误类型。
4. 写入 `ai.agent_memory`。
5. 重新执行受控工具链路。
6. 只有二次结果同时满足 `answer`、数据支撑充分和数字一致，才替换原结论。
7. 否则返回“二次复核后仍缺少充分证据，建议人工核对”。

可推断错误类型：

- 用户指出的错误。
- 缺少工具证据。
- 可能误拒答。
- 年份或筛选条件丢失。
- 指标未完整覆盖。
- 数字或口径不一致。
- 意图识别错误。
- 数据结果可能有误。
- 回答未满足预期。

边界：

- 这不是大模型参数微调。
- 单次否定不能直接覆盖业务口径。
- 反思记忆按用户和学校范围生效。

### 4.6 反思记忆压缩

默认累计 4 条有效反思后压缩。

压缩产物：

- 高频错误代码。
- 后续检查规则。
- `reflection_summary` 记忆。
- 原细粒度反思考核标记为过期。

后续数据问答会检查：

- 是否有工具证据。
- 年份、省份、专业等条件是否保留。
- 是否覆盖可核验指标。
- 数字是否与工具结果一致。

### 4.7 反馈模板权重优化

实现文件：

```text
apps/api/app/modules/agent_intelligence/optimizer.py
packages/agent_core/agent_core/optimizer.py
```

目标分：

```text
target_score = rating / 5
```

梯度：

```text
gradient = current_score - target_score
```

权重更新：

```text
new_weight = clamp(
  previous_weight - learning_rate × gradient,
  0.1,
  3.0
)
```

默认学习率 `0.05`。

记录：

- `ai.response_evaluation`
- `ai.prompt_template`
- `ai.optimization_event`
- `ai.feedback`

这只是模板选择和权重调整，不是神经网络训练。

## 六、统计与业务算法

### 6.1 基础比率

```text
计划完成率 = 录取数 ÷ 计划数 × 100%
报到率 = 报到数 ÷ 录取数 × 100%
未报到人数 = max(录取数 - 报到数, 0)
生源明细覆盖率 = 明细人数 ÷ 官方录取总数 × 100%
咨询转化率 = 转化咨询数 ÷ 咨询总数 × 100%
```

### 6.2 志愿与报考

```text
志愿率 = 志愿次数 ÷ 计划数 × 100%
报考率 = 不同报考考生数 ÷ 计划数 × 100%
一志愿录取率 = 一志愿录取数 ÷ 录取数 × 100%
一志愿报考率 = 一志愿报考数 ÷ 计划数 × 100%
区间志愿录取率 = 区间志愿录取数 ÷ 录取数 × 100%
区间志愿报考率 = 区间志愿报考数 ÷ 计划数 × 100%
调剂率 = 调剂数 ÷ 录取数或计划汇总录取数 × 100%
```

说明：

- 志愿率和报考率是产品分析口径，不等同于省考试院官方口径。

### 6.3 分位数

- 中位分：录取投档分的 50% 分位。
- 下四分位分：约 25% 分位。
- 基于当前录取记录中的有效投档分。

### 6.4 预测算法

实现文件：

```text
apps/api/app/modules/forecast/service.py
```

模型：

```text
y = intercept + slope × x
```

预测区间：

```text
margin = max(
  1.5 × 最大绝对残差,
  5% × 预测值,
  1
)
```

风险：

- 完成率 < 90%：高风险。
- 90%—95%：中风险。
- ≥ 95%：低风险。

置信度：

- 1 个年度数据点：不预测。
- 2 个点：中置信度。
- ≥ 3 个点：高置信度。

### 6.5 异常检测算法

当前年与上一年按专业比较。

高风险：

- 计划或录取为 0。
- 完成率 < 90%。
- 志愿热度比 ≥ 3。

中风险：

- 完成率 90%—95%。
- 志愿热度比 < 0.5。
- 计划同比变化 ≥ 15%。
- 录取同比变化 ≥ 15%。

输出：

- 异常原因。
- 风险等级。
- AI 建议。
- 志愿热度比。
- 计划与录取同比。

### 6.6 计划沙盘算法

需求因子：

```text
demand_factor =
clamp(志愿次数 ÷ 计划数 ÷ 3, 0.5, 1.2)
```

预计录取：

```text
min(
  新计划,
  max(0, 原录取 + 计划增减 × demand_factor)
)
```

预计分数变化：

```text
-计划增减 × 0.08
```

风险：

- 模拟完成率 < 90%：高。
- 90%—95%：中。
- ≥ 95%：低。

### 6.7 扩招决策算法

支持条件：

- 志愿热度比 ≥ 1.2。
- 下一年预测完成率 ≥ 95%。
- 模拟完成率 ≥ 95%。

阻断或不建议：

- 志愿热度比 < 0.8。
- 预测完成率 < 90%。
- 模拟完成率 < 90%。

审慎：

- 志愿热度比在 0.8—1.0。
- 预测完成率 90%—95%。
- 模拟完成率 90%—95%。
- 模拟分数变化低于 -3 分。

建议扩招区间：

- 支持：约现有计划的 5%—10%。
- 审慎：约 2%—5%。
- 不建议：0—2%，并先处理风险。

该模型是启发式模拟，不是因果模型。
