# 运行时性能与可观测性

- 日期：2026-11-07
- 版本：ECSP-Admissions-G1.1
- 范围：新版智能体问数链路

## 一、目标

在不改变页面和业务功能的前提下，使系统能够持续观测：

- P50 / P95 / P99 延迟
- 工具缓存命中率
- 双规划触发率
- MiniMind 超时率和拒绝率
- 回答、澄清、拒答比例
- 每次问答的工具数量和路由模式

## 二、指标接入

实现文件：

- `apps/api/app/core/runtime_metrics.py`
- `apps/api/app/modules/agent/service.py`
- `apps/api/app/modules/agent/hybrid_adapter.py`
- `apps/api/app/modules/agent/router.py`

新版智能体每次问数完成后记录：

- 完整问数耗时
- `fast` 或 `model` 路由
- 工具调用数量
- `l1`、`l2`、`miss` 缓存层
- 是否触发双规划
- 最终策略：`answer`、`clarify`、`no_data`、`no_permission`、`out_of_scope`、`insufficient_data`

指标优先写入 Redis；Redis 不可用时使用进程内窗口，适配当前单实例演示部署。

## 三、缓存遥测

工具首次执行：

```text
cache_hit=false
_cache_layer=miss
```

相同工具和参数再次执行：

```text
cache_hit=true
_cache_layer=l1
```

学生档案和学生统计属于敏感工具，始终绕过缓存：

```text
_cache_layer=bypass
```

`_cache_layer` 仅用于内部指标统计，在返回接口前会被移除；`cache_hit` 保留供调用方观察。

## 四、HTTP 探针结果

通过正式 `3000` 演示环境执行：

1. 登录。
2. 连续两次提交同一问题。
3. 读取 `/api/v1/agent/metrics`。

结果：

| 指标 | 结果 |
|---|---:|
| 问数次数 | 2 |
| 缓存未命中 | 1 |
| 缓存 L1 命中 | 1 |
| 缓存命中率 | 50% |
| 首次工具缓存 | 未命中 |
| 第二次工具缓存 | 命中 |
| 首次策略 | answer |
| 第二次策略 | answer |
| P50 | 4.7 ms |
| P95 | 51.6 ms |
| P99 | 51.6 ms |
| 快速路由率 | 100% |
| 双规划触发率 | 0% |
| MiniMind 超时率 | 0% |

该测试证明缓存和延迟指标不是静态展示值，而是由真实 HTTP 问数链路产生。

## 五、完整响应契约

`/api/v1/agent/chat` 现在保留治理字段：

- `semantic_slots`
- `slot_ambiguity`
- `evidence_certificates`
- `numeric_verification`
- `plan_consistency`
- `risk_decision`
- `verification_summary`
- `clarification`
- `algorithm_version`
- `reasoning_trace`
- `memory_count`
- `knowledge_count`
- `charts`
- `table`

此前响应模型会丢弃这些字段，调用方无法看到证据和拒答依据；现已补齐并加入单元测试。

## 六、部署优化

后端 Dockerfile 调整为：

```text
复制应用代码
→ 安装 Python 依赖
→ 复制脚本、评测资料和模型
```

这样仅修改脚本、评测集或模型文件时，不会使 Python 依赖安装层失效，可缩短后续镜像重建时间。

## 七、当前边界

- 指标窗口当前基于单实例内存或可选 Redis。
- HTTP 探针不是并发压测。
- P50/P95/P99 只代表当前两个探针样本，不是 2 核 4G 容量结论。
- MiniMind 未启用，因此模型超时率和双规划触发率均为 0。
- 多实例部署必须启用共享 Redis 指标，否则各实例指标独立。
