# ECSP 数学形式化与实现映射

- 日期：2026-11-07
- 版本：ECSP-Admissions-G1.2
- 方法：Evidence-Constrained Selective Planning
- 中文：面向招生敏感数据的证据约束选择性多规划方法

## 一、优化目标

在隐私不泄露、无依据回答受控和延迟预算满足的条件下，最大化正确回答覆盖率：

\[
\max_{\pi}\ \mathrm{Coverage}(\pi)
\]

约束：

\[
\mathrm{FalseAnswerRate}(\pi)\leq \alpha
\]

\[
\mathrm{UnsupportedAnswerRate}(\pi)\leq \alpha
\]

\[
\mathrm{PrivacyViolation}(\pi)=0
\]

\[
P95Latency(\pi)\leq L
\]

当前工程默认值：

```ini
AGENT_UNSUPPORTED_ANSWER_ALPHA=0.0
AGENT_P95_LATENCY_BUDGET_MS=2000
AGENT_RISK_THRESHOLD=0.32
AGENT_PLAN_CONSISTENCY_THRESHOLD=1.0
```

说明：

- `Coverage`：可正确回答的问题占全部问题的比例。
- `FalseAnswerRate`：回答中错误答案的比例。
- `UnsupportedAnswerRate`：回答中数字或结论缺少工具证据的比例。
- `PrivacyViolation`：越权访问、敏感字段泄露、名单导出或小样本泄露次数。
- `P95Latency`：同一部署和负载配置下的问数 P95 延迟。
- `L`：系统允许的 P95 延迟预算。

## 二、槽位熵与语义不确定性

单个槽位的候选分布为 \(p_j\) 时：

\[
H_s=-\sum_j p_j\log p_j
\]

为便于跨槽位比较，实现同时计算归一化熵：

\[
\tilde H_s=
\begin{cases}
H_s/\log n_s,&n_s>1\\
0,&n_s\leq1
\end{cases}
\]

关键槽位加权语义不确定性：

\[
U_{sem}=\sum_s w_s\tilde H_s
\]

默认槽位权重：

| 槽位 | 权重 |
|---|---:|
| `metric` | 0.30 |
| `year` | 0.15 |
| `major` | 0.20 |
| `student_identity` | 0.20 |
| `province` | 0.10 |
| 其他 | 0.05 |

实现位置：

```text
packages/agent_core/agent_core/formal.py
packages/agent_core/agent_core/semantics.py
```

实际接入方式：

```text
risk_ambiguity =
max(rule_ambiguity,
    min(0.65, 0.5 × U_sem))
```

规则歧义继续负责强业务口径判断；熵只补充可计算的候选不确定性，不替代已校准的业务规则。

## 三、结果相似度

定义为：

\[
A(q)=\mathrm{Sim}(R_1,R_2)
\]

只有当：

\[
A(q)\geq\tau_A
\]

当前连续相似度由三部分组成：

- 指标相似度：数值相对误差、非数值精确匹配。
- 表格相似度：列集合 Jaccard 与行集合 Jaccard。
- 数据源相似度：数据源集合 Jaccard。

综合相似度取已存在证据组件的平均值，再乘以工具覆盖率和结果覆盖率。

默认：

```text
tau_A = 1.0
```

设置为 `1.0` 是为了保持与原有“规范化结果完全一致”行为兼容。后续在独立校准集上验证后，可以调整到小于 1 的容忍阈值。

实现位置：

```text
packages/agent_core/agent_core/verification.py
```

函数：

```text
result_similarity()
compare_plan_results()
build_plan_consistency()
```

## 四、Answer 形式条件

形式化回答条件：

\[
\mathrm{Answer}
\iff
\mathrm{ConstraintsComplete}
\land
\mathrm{EvidenceSufficient}
\land
\mathrm{ResultConsistent}
\land
\mathrm{PermissionAllowed}
\land
\mathrm{RiskBelowThreshold}
\]

实现后，每次风险决策输出：

```json
{
  "constraints_complete": true,
  "evidence_sufficient": true,
  "result_consistent": true,
  "permission_allowed": true,
  "risk_below_threshold": true,
  "can_answer": true
}
```

各条件定义：

| 条件 | 实现含义 |
|---|---|
| `constraints_complete` | 不存在需澄清的高风险歧义、缺失必填槽位或无法执行的别名 |
| `evidence_sufficient` | 证据完整度、数字覆盖率、数据支撑度均达到要求，且不是明确无数据 |
| `result_consistent` | 多计划规范化结果相似度达到 \(\tau_A\) |
| `permission_allowed` | 不存在权限、隐私或名单导出违规 |
| `risk_below_threshold` | 风险分不高于回答阈值 |

实现位置：

```text
packages/agent_core/agent_core/formal.py
packages/agent_core/agent_core/risk.py
packages/agent_core/agent_core/runtime.py
```

## 七、并发约束结果

在 2 核 4G 形态隔离环境中：

| 并发 | P95 | 是否满足 L=2000 ms |
|---|---:|---|
| 12 | 1895.97 ms | 是 |
| 24 | 6345.67 ms | 否 |

因此当前演示建议最大并发为 12—16；24 并发虽然零错误，但违反当前延迟预算。
