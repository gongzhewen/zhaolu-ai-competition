# PPT 技术口径更新清单

- 日期：2026-11-08
- 用途：将现有答辩 PPT 的技术页更新到真实冻结实验口径
- 原则：少讲通用大模型术语，重点讲“证据约束、受控工具、边界收敛和可复核实验”

## 第 1 页：问题定义

建议文字：

> 高校招生数据包含计划、录取、报到、成绩、志愿和敏感个人信息。通用大模型直接回答容易出现数字幻觉、口径漂移和越权输出。需要一种只在高证据、高一致性和权限允许时回答的招生分析智能体。

## 第 2 页：产品定位

建议文字：

> 招录智策不是通用聊天机器人，而是面向高校招生管理部门的 AI 数据分析系统。模型负责理解与规划，业务数字由受控工具查询 MySQL 产生，回答前经过证据、数值、安全性、一致性和权限校验。

## 第 3 页：整体架构

保留现有架构图，文字改为：

```text
自然语言问题
→ 规则/ONNX/MiniMind 意图路由
→ 语义槽位与歧义估计
→ 单工具或多工具规划
→ MySQL 受控查询
→ 数字证据证书
→ 风险与隐私门控
→ 结构化回答
```

强调：

- 模型不直接编造业务数字。
- 工具查询与权限边界分离。
- 无法验证时允许澄清、无数据或拒答。

## 第 4 页：核心算法机制

建议文字：

> 输入问题先形成候选规划集合，计划必须满足指标、年份、范围、权限和证据完整性约束。数字级证据证书记录数值来源、查询字段和一致性；低证据或高歧义问题进入澄清或拒答，不参与“看起来合理”的生成。

不要写：

- “行业首个”
- “完全原创理论”
- “100% 通用准确率”

## 第 5 页：真实冻结实验设计

建议文字：

- 校准集：2022—2023，120 题。
- 测试集：2024—2025，120 题。
- 2026：仅公开演示。
- 每题有独立 SQL 标准答案。
- 测试集不用于调参。
- 2024—2025 已在早期开发中被观察，因此是事后冻结留出集。

## 第 6 页：基线对比

保留表格，使用以下数字：

| 方法 | 总体准确率 | P95 |
|---|---:|---:|
| G0 规则 + 工具 | 91.67% | 494 ms |
| B1 仅本地 RAG | 0% | 20 ms |
| B2 本地 Text-to-SQL | 16.67% | 54.6 s |
| 完整算法 | 100% | 498 ms |

补充限定：

> 完整算法为 120 题事后冻结测试集上的用户可见证据一致率；工具精确匹配率为 87.50%。

## 第 7 页：消融实验

建议文字：

| 消融 | 结果 |
|---|---|
| 关闭别名归一化 | 应答题准确率从 100% 降至 87.5%，误拒答率升至 12.5% |
| 关闭隐私硬约束 | 正确拒答率从 100% 降至 70.83%，出现 5 次隐私违规 |

结论：

> 别名归一化解决跨省名称和口语表达映射；隐私硬约束不是附加功能，而是回答准入条件。

## 第 8 页：部署与断网验收

建议文字：

> MySQL、后端和 Nginx 支持 Docker 部署；本地模型与业务系统解耦。断网模拟下禁用外部 API 和本地 SQL 模型，9 个端到端问题执行 3 轮，27/27 通过，P95 约 907 ms。

## 第 9 页：限制与未来规划

必须保留：

- 120 题样本有限。
- 事后冻结，不是前瞻盲测。
- 双规划触发 0 次，收益尚未证明。
- B2 本地 3B 模型延迟过高。
- 真实浏览器 19 页面桌面/手机交互回归尚未完成。
- 签字授权书和业务负责人签核仍待补。
- 后续扩大试点、配对显著性检验、真实反馈和业务效益数据。

## 答辩统一表述

不要说：

> 我们的智能体准确率 100%。

应说：

> 在当前 120 题真实授权数据事后冻结测试集上，完整算法的用户可见证据一致率为 100%，95% 置信区间为 100%—100%，工具精确匹配率为 87.50%；该结果不能外推为任意学校的普遍准确率。
