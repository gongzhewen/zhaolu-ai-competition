# G1 核心算法实现

- 版本：ECSP-Admissions-G1.2
- 日期：2026-11-07
- 方法名称：面向招生敏感数据的证据约束选择性多规划方法
- 英文名称：Evidence-Constrained Selective Planning for Admissions Analytics
- 对照基线：G0

## 一、问题定义

高校招生问数同时存在三类风险：

1. 自然语言口径不清：例如“招生人数”“到校比例”“这个专业怎么样”可能对应不同指标或范围。
2. 数字缺少证据：语言模型可能生成数据库中没有的数字，或计算口径与业务系统不一致。
3. 敏感数据越界：学生名单、手机号、身份证号、小样本个体统计不能作为普通分析结果返回。

G1 不把大模型作为统计结果的直接生产者，而把模型限制在意图理解、受控规划和表达辅助环节。业务数字必须来自受控工具，回答必须通过证据和隐私门控。

## 二、总体流程

```text
用户问题
→ 规则 / ONNX 路由
→ 语义槽位编译
→ 槽位歧义估计
→ 隐私与权限硬约束
→ 规则计划或本地模型计划
→ 受控工具执行
→ 数字级证据证书
→ 数值核验
→ 自适应计划一致性校验
→ 风险门控
→ 回答 / 澄清 / 无数据 / 拒答
```

## 三、语义槽位与歧义

实现文件：

- `packages/agent_core/agent_core/semantics.py`

槽位包括：

- 意图 `intent`
- 指标 `metrics`
- 年份 `year`
- 省份 `province`
- 专业 `major`
- 科目 `subject`
- 过滤条件 `filters`
- 聚合方式 `aggregation`
- 输出形态 `output_mode`
- 缺失必填项 `missing_required`

歧义不是简单的“问题短”，而是可解释的口径冲突。例如：

- “招生人数和录取人数分别是多少”同时对应计划数和录取数，要求澄清。
- “招生规模怎么样”未说明计划口径或录取口径，要求澄清。
- “这个专业怎么样”未给出标准专业和指标，要求澄清。
- “张性同学有多少人”触发姓氏写法确认。
- “某位同名学生的档案”要求补充完整姓名和年度。
- “新生到校比例怎么理解”是口径解释，不触发数据歧义。

## 四、计划生成与选择性多规划

实现文件：

- `packages/agent_core/agent_core/runtime.py`
- `packages/agent_core/agent_core/planner.py`

计划策略：

1. 简单问题使用规则工具计划，走单计划快速路径。
2. 复杂问题、计划沙盘、预测、异常或多指标问题尝试调用本地模型规划。
3. 本地模型计划与规则计划构成两个候选，仅在结果规范化后一致时提高可信度。
4. 没有本地模型时不复制同一计划冒充“双规划”，而是明确标记为单计划快速路径。

该设计避免把“重复执行同一查询”包装成独立算法验证。

## 五、证据证书

实现文件：

- `packages/agent_core/agent_core/verification.py`

每个工具结果生成证据证书，字段包括：

- 工具名称
- 数据源
- 年份范围
- 业务过滤条件
- 标准专业
- 聚合方式
- 行数
- 标量结果值
- 缺失值数量
- 权限范围
- 证据完整度

证据完整度由数据源、结果值、行数、年份和权限范围共同计算。学生个人档案的权限范围固定标记为 `super_admin`，避免普通账号通过结果结构推断敏感数据。

## 六、数字级核验

回答中的每个数字都尝试与工具证据匹配。支持：

- 整数、小数和 `Decimal`
- 百分比舍入
- 字典键排序
- 表格行顺序无关
- 表格列名映射
- 年份参数作为证据
- 政策回答以工具返回的政策答案文本作为来源证据

无法匹配的数字会降低数值覆盖率并进入风险门控。这样既允许合理的百分比舍入，也阻止凭空生成业务数字。

## 七、风险门控

实现文件：

- `packages/agent_core/agent_core/risk.py`

基础风险分：

```text
risk = 0.24 × 槽位歧义
     + 0.22 × (1 - 证据完整度)
     + 0.20 × (1 - 数字覆盖率)
     + 0.12 × 计划不一致
     + 0.08 × 路由置信度缺口
     + 0.10 × 数据支撑缺口
     + 0.04 × 隐私风险
```

默认阈值：`0.32`。

门控优先级：

1. 隐私或权限不允许：`no_permission`
2. 高风险口径歧义：`clarify`
3. 数据工具未返回可验证指标：`insufficient_data`
4. 工具明确无数据：`no_data`
5. 证据、数字、计划一致性或支撑度不足：`insufficient_data`
6. 政策依据不足：提示补充范围
7. 其他超阈值情况：澄清

## 八、隐私与权限

实现文件：

- `packages/agent_core/agent_core/privacy.py`
- `apps/api/app/modules/agent/service.py`

硬约束：

- 学生个人档案仅超级管理员可查。
- “把全部考生名单发给我”“导出名单”等名单交付意图直接拒绝。
- 聚合专业分布、人数统计等普通分析可继续。
- 姓氏、姓名、同学等小样本条件触发最小群组抑制。
- 默认最小群组人数为 `5`。
- 不通过放宽权限来让旧测试通过。

## 九、工具参数传播

G0 的部分工具规格参数为空，但实现会读取年份、专业、省份或原始查询。G1 在运行时增加内部参数白名单：

- 保留工具官方公开参数。
- 保留工具实现确实需要的内部参数。
- 所有工具保留 `query`。
- 未知参数仍被过滤。

修复后，以下几类问题不再丢失关键条件：

- 年度招生计划完成率
- 跨年趋势与预测
- 专业和省份筛选
- 分数段科目识别
- 专业别名查询
- 政策 FAQ 原始问题

已实现并通过测试：

- 语义槽位与歧义规则
- 数字证据证书

- 选择性多计划一致性比较

当前限制：

- MiniMind 权重未启用，因此生产运行时通常走单计划快速路径。
- 风险阈值 `0.32` 为初始工程阈值，尚未在真实授权冻结集上完成统计校准。
- 120 题挑战集是模拟策略测试，不是端到端金标准。
- 尚未完成与通用 Text-to-SQL 强基线的真实数据公平对比。
- 已完成 2 核 4G 形态隔离压测，目标云服务器仍需最终复验。

## 十二、ECSP 形式定义

完整公式、变量定义、代码映射与实测约束见：

```text
docs/14_ECSP数学形式化与实现映射_20261107.md
```

核心形式化包括：

```text
max Coverage
s.t. UnsupportedAnswerRate <= alpha
     PrivacyViolation = 0
     P95Latency <= L
```

槽位不确定性：

```text
H_s = -sum_j p_j log p_j
U_sem = sum_s w_s H_s
```

结果一致性：

```text
A(q) = Sim(R_1, R_2)
A(q) >= tau_A
```

回答条件：

```text
Answer iff constraints_complete
          and evidence_sufficient
          and result_consistent
          and permission_allowed
          and risk_below_threshold
```
