# 招录智策上传包与宝塔服务器部署详细教程

日期：2026-10-21

适用上传包：

```text
zhaolu-ai-rag-router-update-20261021.zip
```

## 一、部署前先确认

### 1. 推荐服务器环境

- Ubuntu 22.04 或 Ubuntu 24.04
- 宝塔面板
- Docker 与 Docker Compose 已安装
- 建议至少 2 核 4 GB
- 系统盘至少保留 5 GB 可用空间
- 已开放 80 和 443 端口
- 如使用域名，域名 A 记录已经指向服务器公网 IP

### 2. 本次容器关系

```text
浏览器
→ 宝塔 Nginx 站点
→ 127.0.0.1:8080
→ zhaolu-ai-v2-web 容器
→ /api 转发到 backend:8000
→ zhaolu-ai-v2-backend 容器
→ mysql:3306
```

默认只对服务器本机开放：

```text
BACKEND_PORT=8000
WEB_PORT=8080
```

不要直接向公网开放 8000 或 8080。

### 3. 上传包结构

ZIP 解压后顶层直接是：

```text
apps/
deploy/
docs/
models/
packages/
scripts/
tests/
docker-compose.baota.yml
docker-compose.yml
pyproject.toml
.env.baota.example
```

不会再套一层 `02_软件源码`。

## 二、必须先生成的配置

进入项目目录后创建 `.env.baota`。

```bash
cd /www/wwwroot/zhaolu-ai-v2
cp .env.baota.example .env.baota
nano .env.baota
```

至少检查以下配置：

```ini
MYSQL_ROOT_PASSWORD=只含字母数字的强密码
MYSQL_DATABASE=zhaolu_v2
MYSQL_USER=zhaolu_app
MYSQL_PASSWORD=只含字母数字的强密码
BACKEND_PORT=8000
WEB_PORT=8080
JWT_SECRET=使用随机命令生成
AGENT_FAST_MODE=true
AGENT_MIN_DATA_SUPPORT=0.65
AGENT_CHAT_TIMEOUT_SECONDS=45
AGENT_STREAM_HEARTBEAT_SECONDS=5
MINIMIND_ENABLED=false
REDIS_ENABLED=false
DEMO_FORCE_RESET=0

RAG_VECTOR_ENABLED=true
RAG_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
RAG_EMBEDDING_CACHE_DIR=./models/embedding
RAG_EMBEDDING_TIMEOUT_SECONDS=20
RAG_VECTOR_WEIGHT=0.55

ROUTER_ML_ENABLED=true
ROUTER_ML_MODEL_PATH=./models/router/router.onnx
ROUTER_ML_TOKENIZER_PATH=./models/router/tokenizer.json
ROUTER_ML_LABEL_MAP_PATH=./models/router/label_map.json
ROUTER_ML_CONFIDENCE_THRESHOLD=0.5
```

生成 JWT 密钥：

```bash
openssl rand -hex 32
```

将输出填入：

```ini
JWT_SECRET=生成出来的一整串内容
```

### 密码注意事项

`MYSQL_PASSWORD` 和 `MYSQL_ROOT_PASSWORD` 建议只使用字母和数字。

不要使用：

```text
@ : / # ? %
```

因为数据库连接 URL 会解析这些字符，容易出现“主机名被截断”“认证失败”或连接串错误。

## 三、全新服务器部署

以下步骤只适用于数据库为空、第一次部署的情况。

### 1. 上传 ZIP

使用宝塔文件管理器上传到：

```text
/www/wwwroot/zhaolu-ai-rag-router-update-20261021.zip
```

也可以使用 SSH：

```bash
scp zhaolu-ai-rag-router-update-20261021.zip root@服务器IP:/www/wwwroot/
```

### 2. 校验上传包

```bash
cd /www/wwwroot
sha256sum zhaolu-ai-rag-router-update-20261021.zip
```

应与交付说明中的 SHA256 完全一致。

### 3. 解压

```bash
cd /www/wwwroot
unzip zhaolu-ai-rag-router-update-20261021.zip -d zhaolu-ai-rag-router-update-20261021
```

### 4. 创建项目目录并复制源码

```bash
cd /www/wwwroot
cp -a zhaolu-ai-rag-router-update-20261021 zhaolu-ai-v2
cd /www/wwwroot/zhaolu-ai-v2
cp .env.baota.example .env.baota
```

然后编辑 `.env.baota`。

### 5. 先启动 MySQL

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  up -d mysql
```

等待健康状态：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  ps
```

MySQL 显示 `healthy` 后继续。

### 6. 构建后端镜像

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  build --no-cache backend
```

这一步会把 `models/embedding` 和 `models/router` 打进后端镜像。

### 7. 演示数据初始化

仅当数据库为空且需要演示数据时执行：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  --profile demo \
  run --rm demo-init
```

如果使用自己的 SQL 备份导入，不要执行这一步。

更新包已将 `demo-init` 放入 `demo` profile，普通 `up -d` 不会自动重复写入演示数据。

### 8. 启动后端和前端

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  up -d
```

检查：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  ps
```

### 9. 本机验证

```bash
curl http://127.0.0.1:8000/api/v1/health
```

预期包含：

```json
{"status":"ok"}
```

```bash
curl http://127.0.0.1:8000/api/v1/agent/capabilities
```

重点核对：

```text
tool_count=17
rag_vector_enabled=true
router_ml_enabled=true
```

## 五、宝塔站点与反向代理

### 1. 创建站点

宝塔面板：

```text
网站 → 添加站点
```

域名填写自己的域名。

本项目前端由 Docker 的 Nginx 容器提供，宝塔站点只负责公网入口和 HTTPS 反向代理。

### 2. 设置反向代理

宝塔：

```text
网站 → 目标站点 → 反向代理 → 添加反向代理
```

填写：

```text
代理名称：zhaolu-ai
目标 URL：http://127.0.0.1:8080
发送域名：$host
```

如果宝塔不能选择 `$host`，使用下面的 Nginx 配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
    proxy_send_timeout 60s;
}
```

### 3. 域名解析

先确认域名 A 记录：

```bash
dig +short A gzwxdom.top
```

必须返回服务器公网 IP。

同时检查安全组和防火墙是否开放：

```text
80/tcp
443/tcp
```

### 4. 申请 HTTPS

DNS 生效后再在宝塔申请 Let's Encrypt 证书。

如果出现：

```text
no valid A records found
```

不要反复点击申请，先解决 DNS：

1. 检查域名是否拼写正确。
2. 检查 A 记录是否指向当前服务器公网 IP。
3. 使用 `dig` 或 `nslookup` 确认。
4. 等待 DNS 缓存过期。
5. 再申请证书。

## 七、常见问题

### 1. `Bind for 0.0.0.0:8000 failed: port is already allocated`

原因：8000 端口被旧容器或其他进程占用。

检查：

```bash
ss -lntp | grep :8000
docker ps
```

处理：

```bash
docker stop 旧容器名
```

或修改 `.env.baota`：

```ini
BACKEND_PORT=8001
```

然后重建并启动。

### 2. 缺少环境变量警告

常见原因：

- 不在项目目录执行。
- `--env-file .env.baota` 路径写错。
- `.env.baota` 文件名错误。

统一从项目目录执行：

```bash
cd /www/wwwroot/zhaolu-ai-v2
ls -l .env.baota
```

### 3. `Duplicate entry '1' for key 'school.PRIMARY'`

原因：对已有数据库重复执行了演示数据初始化。

不要执行：

```bash
python scripts/seed_mysql_demo.py
```

不要运行：

```bash
--profile demo run --rm demo-init
```

更新包已让普通 `up -d` 不执行 `demo-init`。

如果已经误执行，先查看日志，不要直接删除 volume。

### 4. `couldn't find env file`

说明当前执行目录错误，或用了错误的绝对路径。

正确方式：

```bash
cd /www/wwwroot/zhaolu-ai-v2
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  ps
```

### 5. 向量 RAG 回退

日志出现：

```text
Chinese vector RAG unavailable; falling back to lexical retrieval
```

检查模型是否进入镜像：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  exec backend find models/embedding -name model_optimized.onnx -ls
```

如果文件不存在，重新执行后端 `build --no-cache`。

### 6. 页面显示 Not Found

检查：

```bash
curl http://127.0.0.1:8080
```

如果本机 8080 正常，问题在宝塔反向代理。

如果本机 8080 不正常，查看 `web` 和 `backend` 容器状态。

### 7. 登录后马上失效

检查 `JWT_SECRET`：

- 是否超过 32 位。
- 是否在重启后被修改。
- 浏览器是否仍带旧 token。

修改 JWT 后需要重新登录。

### 8. 修改数据库密码后认证失败

关键：修改 `.env.baota` 不会自动修改已有 MySQL volume 中的用户密码。

已有数据库时，优先保持原密码不变。

如果确实要改，需要进入 MySQL 执行：

```sql
ALTER USER 'zhaolu_app'@'%' IDENTIFIED BY '新密码';
FLUSH PRIVILEGES;
```

然后同步修改 `.env.baota`。

### 9. 特定问题返回 502 或 504

如果只有少数问题出现 502 或 504，先检查后端是否退出、被系统杀死或向量模型加载超时：

504 表示宝塔或容器 Nginx 等不到后端响应。修正版给中文向量模型加载增加了 20 秒硬超时：

```ini
RAG_EMBEDDING_TIMEOUT_SECONDS=20
```

超时后立即回退关键词检索并返回 200，不再让请求一直挂到网关超时。

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  logs --tail=200 backend
```

检查 OOM：

```bash
docker inspect zhaolu-ai-v2-backend-1 \
  --format 'OOMKilled={{.State.OOMKilled}} ExitCode={{.State.ExitCode}}'
```

如果是旧版包中“新生到校比例怎么理解”触发 502，原因通常是：

- 规则误判为招生总览。
- 第一次加载 121 MB ONNX 意图模型。
- 容器冷启动较慢或内存不足。
- Nginx 无法连接后端，于是返回 502，而不是业务错误。

当前修正版已做以下处理：

- 该问题改为进入 `policy_faq`，走中文向量知识检索。
- ONNX 路由加载失败时自动回退规则路由，不再让异常直接冒到接口。
- 后端内存上限调整为 1100 MB。

确认运行的是修正版：

```bash
grep -n '怎么理解' packages/agent_core/agent_core/router.py
grep -n 'ONNX intent router unavailable' apps/api/app/modules/agent/ml_router.py
```

确认后重新构建：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  build --no-cache backend

docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  up -d --force-recreate backend web
```

如果仍然 502，可临时关闭 ONNX 路由确认原因：

```ini
ROUTER_ML_ENABLED=false
```

然后：

```bash
docker compose \
  -p zhaolu-ai-v2 \
  --env-file .env.baota \
  -f docker-compose.baota.yml \
  up -d --force-recreate backend
```

如果关闭 ONNX 后恢复正常，应检查模型文件是否完整以及 Docker 内存限制，不要把关闭模型当成最终方案。
