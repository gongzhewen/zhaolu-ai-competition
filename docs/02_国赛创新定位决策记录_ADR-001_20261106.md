## 一、已确认的官方定位

> 我们针对高校招生敏感结构化数据，提出一种场景化的证据约束选择性问数方法。

建议正式名称：

> 面向招生敏感数据的证据约束选择性多规划方法

英文名称：

> Evidence-Constrained Selective Planning for Admissions Analytics

上述定位和名称是国赛阶段的官方表述。除非用户明确决定修改，后续作品方案、PPT、答辩 Q&A、算法说明、测试报告和代码注释均以该定位为准。

## 二、必须记住的一句话

招录智策不是让大模型替学校猜答案，而是：

> 让 AI 理解招生业务问题，让软件强制执行数据和权限边界，让验证机制证明每个数字都有来源。

系统的核心价值不是“增加一个聊天框”，而是成为现有招生业务系统与学校决策人员之间的可信招生数据决策层。

## 三、决策背景

省赛答辩中，评委提出“重复造轮子”。这一判断有现实依据：

- 规则路由是成熟技术。
- ONNX 意图分类是成熟技术。
- BGE 向量检索和 RAG 是成熟技术。
- 受控工具调用是成熟技术。
- MySQL、缓存和物化视图是成熟工程手段。
- 如果创新点仅写“把这些技术组合起来”，容易被理解为工程集成。

因此，国赛不能继续用技术栈堆叠作为主要创新叙事，必须明确提出：

1. 一个真实的招生业务问题。
2. 原通用方法在该场景中的具体失败模式。
3. 一到两个能够改掉失败模式的核心机制。
4. 使用强基线、冻结测试集和消融实验证明增益。
5. 用本地私有化部署证明方案适用于敏感数据场景。

## 四、最终选择的问题定义

高校招生问数需要同时满足四项要求：

1. 用户问题往往是口语化、模糊和不完整的。
2. 招生指标和数据口径具有强业务约束。
3. 敏感数据不能发送到外部模型或云端服务。
4. 错误数字的代价高于暂时不回答。

因此将问题定义为：

> 在隐私不泄露、数字有证据、错误风险受控的条件下，最大化能够正确回答的问题覆盖率。

形式化为：

```text
max Coverage
```

约束为：

```text
UnsupportedAnswerRate <= alpha
PrivacyViolation = 0
P95Latency <= L
```

其中：

- Coverage：系统能够正确回答的问题比例
- UnsupportedAnswerRate：已回答问题中数字或结论缺乏证据的比例
- PrivacyViolation：越权查询、敏感字段导出或违反数据边界的次数
- L：本地部署环境允许的最大 P95 延迟
- alpha：业务允许的无依据回答风险上限

这不是为了凑数学公式，而是把“回答、澄清和拒答”变成一个可测量、可校准的系统决策问题。

## 五、核心方法定位

正式方法名称：

> 面向招生敏感数据的证据约束选择性多规划方法

简称可在内部使用：

> ECSP-Admissions

该方法由以下能力组成：

```text
用户自然语言问题
→ 多候选招生语义编译
→ 槽位级歧义估计
→ 招生硬约束过滤
→ 单计划或自适应双计划
→ 受控工具与数据库执行
→ 数字级证据证书
→ 规范化结果一致性比较
→ 隐私与权限硬约束检查
→ 风险校准门控
→ 回答 / 澄清 / 拒答
→ 审计与版本记录
```

### 1. 招生语义编译

将问题转换为结构化槽位：

- 意图
- 指标
- 年份
- 省份
- 专业
- 科类
- 批次
- 筛选条件
- 聚合方式
- 输出形式

招生计划、录取人数、报到人数、成绩、志愿等指标不得混用。

### 2. 槽位级歧义估计

对年份、指标、专业、筛选条件等关键槽位计算候选之间的分歧。

指标、年份和专业等关键槽位存在明显歧义时，优先澄清，不允许模型猜测。

典型示例：

- “新生到校比例”可能指录取新生报到率、计划完成率或未报到率。
- “张性同学”可能存在错字、姓氏或姓名歧义。
- “政治考了 66 分的人有多少”必须明确统计范围、年度和聚合方式。

### 3. 自适应多规划

- 简单单条件问题：只执行一个计划，控制延迟。
- 高歧义、多条件、跨年度、专业别名复杂的问题：执行第二个独立计划。
- 规范化两个计划的结果并计算一致性。
- 结果不一致时检查约束和字段，仍不一致则拒答或澄清。
- 高风险隐私请求不进入多规划，直接拒绝。

多规划只用于高风险问题，避免所有请求都增加模型调用和延迟。

### 4. 数字级证据证书

每一个关键数字必须能够关联：

- 使用的工具
- 数据表或数据源
- 查询年份
- 筛选条件
- 专业标准名称
- 聚合方式
- 返回行数
- 是否存在缺失值
- 是否存在口径转换

没有足够证据的数字不得进入最终回答。

### 5. 风险校准门控

回答前综合检查：

- 意图和槽位歧义
- 必填约束完整度
- 专业别名匹配度
- 工具结果和证据完整度
- 多计划结果一致性
- 数据权限和隐私风险
- 当前延迟预算

只有在硬约束全部满足且综合风险低于校准阈值时回答，否则澄清或拒答。

## 六、为什么选择这个方向

### 1. 它不是硬造新数学公式

单个组件已有大量研究和产品，但强行提出一个与产品脱节的公式没有价值。

真正需要的是：

- 合适的业务问题定义
- 对通用方法失败模式的准确分析
- 与产品功能高度耦合的算法机制
- 可重复的实验证明

### 2. 它同时覆盖三类创新

- 问题定义型创新：风险预算约束下的可验证选择性问数。
- 场景适配型创新：招生槽位、专业别名和业务口径约束。
- 效率优化型创新：只对高风险问题启用第二次规划，适配本地低资源部署。

### 3. 它符合 AI+软件创新赛道

AI 负责处理语言歧义、语义理解和候选规划。

软件负责：

- 确定性工具执行
- 数据库计算
- 权限和隐私边界
- 证据保存
- 审计
- 延迟控制

二者缺少任何一侧都不能形成完整方案：

- 只有 AI，没有软件约束：数字不可信、权限不可控。
- 只有规则和软件，没有 AI：口语、别名、复杂组合问题覆盖不足。

因此创新点不是“用了 AI”，而是 AI 与软件系统形成了互相约束、互相增益的闭环。

## 七、真实数据与隐私原则

已获得老师和学校授权，可以在受控范围内使用近五年真实招生数据开展本地离线研发和评测。

使用边界：

1. 真实数据只用于校内受控环境的本地研发、校准和离线评测。
2. 原始学生明细不得进入公开源码包、PPT、演示视频或截图。
3. 真实数据不得发送到外部模型 API、云端分析服务或第三方评测平台。
4. 公开演示继续使用模拟数据。
5. 正式报告只展示聚合指标、脱敏案例和不含个人身份信息的证据。
6. 需要确认授权是否覆盖竞赛研发、内部评测和对外成果展示。
7. 需要记录数据范围、访问人员、保存期限和使用目的。
8. 小样本统计应根据学校数据管理规定进行抑制或合并。

本地私有化不是单独的算法创新，但它是该方法能够用于真实敏感数据场景的必要边界。

## 八、与已有研究和产品的边界

已经存在且不得宣称首次提出的能力：

- RAG
- 工具调用 Agent
- 多候选 Self-Consistency
- Semantic Entropy
- Selective Classification
- Conformal Prediction / Conformal Risk Control
- Trustworthy Text-to-SQL
- 企业自然语言 BI 和语义层分析

市场中也存在 Snowflake Cortex Analyst、Databricks AI/BI Genie、Power BI Copilot、Looker 对话式分析、ThoughtSpot 和国内 BI 智能问数等相近产品。

因此，创新主张必须限定为：

> 在已有语义不确定性、受控工具调用和选择性回答思想基础上，针对高校招生敏感结构化数据，引入招生硬约束、槽位歧义、多计划结果一致性和数字证据门控，并通过授权真实数据冻结测试集验证场景增益。

不得使用：

- “行业首个”
- “原创全新算法”
- “首次提出语义熵”
- “首次提出多智能体一致性”
- “意图准确率 99.48%，所以回答准确率 99.48%”
- 未经正式试点和授权就宣称真实高校全面应用

正式材料中可以使用：

- “提出一种面向招生场景的……”
- “设计并实现……”
- “在授权真实数据冻结测试集上进行消融验证”
- “相较于同一模型和硬件下的通用方法，实测……”

## 九、实验与证明原则

### 1. 强基线

所有对照必须使用：

- 同一个本地基础模型
- 同一个数据库
- 同一份冻结测试集
- 同一台硬件
- 同一套标准答案

建议基线：

| 版本 | 方法 |
|---|---|
| B1 | 通用本地 RAG 问答 |
| B2 | 通用本地 Text-to-SQL 单计划 |
| B3 | 当前 G0：规则 + ONNX + 工具 |
| Ours | 槽位歧义 + 多计划一致性 + 证据门控 |

不能只与“没有数据库的通用大模型”比较，因为这种弱基线不能证明创新。

### 2. 冻结测试集

- 较早年度用于规则、阈值和参数校准。
- 最新完整年度作为冻结测试留出。
- 测试集不进入知识库和提示词调优。
- 标准答案由独立确定性 SQL或人工复核流程生成。
- 公开演示数据和真实评测数据严格分离。

测试问题至少覆盖：

- 单条件统计
- 多条件筛选
- 跨年比较
- 专业别名
- 口语化表达
- 计划、录取、报到口径区分
- 缺失年份或无数据
- 多轮追问
- 越权导出
- 小样本统计
- 超范围问题

### 3. 指标

- 端到端回答准确率
- 数值完全一致率
- 无依据回答率
- 正确拒答率
- 错误拒答率
- 回答覆盖率
- 隐私违规次数
- P50、P95、P99 延迟
- 不同问题类别的分层结果

### 4. 消融实验

至少完成：

1. 去掉专业别名归一化
2. 去掉槽位歧义估计
3. 去掉第二个查询计划
4. 去掉数字证据门控
5. 用固定阈值代替校准阈值
6. 去掉隐私硬约束

只有消融后指标明显下降，才能证明某模块是算法贡献，而不是包装。

## 十、明确拒绝的优化路径

国赛阶段不采用以下做法：

1. 为了显得“算法化”而硬造公式。
2. 只增加功能页面，不改进智能体核心。
3. 只展示技术栈，不说明失败模式和量化收益。
4. 宣称通用大模型完全不能做招生，而忽略强基线。
5. 使用真实学生明细制作公开截图或演示视频。
6. 将 Redis、缓存、物化视图或 Docker 单独包装成核心算法创新。
7. 把意图分类准确率当作最终回答准确率。
8. 在实验完成前预先写死提升百分比。
9. 宣称行业第一、首次提出或原创理论。
10. 为了多规划一致性而让所有请求都承担高延迟。

## 十一、后续实施顺序

### 阶段 A：测试与证据基础设施

1. 建立真实数据冻结挑战集。
2. 建立独立标准答案生成流程。
3. 建立同一模型、数据和硬件下的强基线。
4. 记录当前 G0 的准确率、拒答率、覆盖率和延迟。

### 阶段 B：算法实现

1. 招生语义槽位结构。
2. 槽位级歧义估计。
3. 数字级证据证书。
4. 自适应双规划与结果一致性比较。
5. 风险校准门控。
6. 隐私和权限硬约束接入。

### 阶段 C：实验与产品化

1. 基线对比。
2. 消融实验。
3. 真实数据评测结果。
4. 代表性失败案例与修复案例。
5. 2 核 4G 性能和 P95 延迟验证。
6. 本地断网运行验证。
7. 报告、PPT、答辩 Q&A 和算法说明更新。

## 十二、验收标准

国赛版本至少需要证明：

1. 通用强基线在招生场景中发生可复现的具体错误。
2. 本方法能够针对这些错误降低无依据回答率或提高回答准确率。
3. 回答覆盖率没有因过度拒答而不可接受地下降。
4. P95 延迟仍适合目标部署环境。
5. 消融实验证明核心模块产生实际增益。
6. 真实数据从未离开受控本地环境。
7. 关闭外部网络后核心问数仍能运行。
8. 所有公开材料只使用模拟数据或脱敏聚合结果。

## 十三、版本记录约定

- G0：2026-10-22 源码基线，记录当前已有功能。
- G1：开始接入证据约束、多规划或风险门控后的第一个功能版本。
- G2：完成测试集、基线、消融和性能优化后的候选国赛版本。
- 后续每个版本必须记录代码变化、功能变化、性能变化、测试结果和回退方式。

本 ADR 固定核心定位、创新边界和实验原则。具体实现可以演进，但不得在没有明确理由和新实验证据的情况下改变官方定位。
