## 二、服务器部署方式

项目目录示例：

```text
/www/wwwroot/zhaolu-ai-v2
```

### 1. 备份

先备份数据库和项目目录，不能跳过。

### 2. 上传并解压更新包

```bash
cd /www/wwwroot
unzip zhaolu-ai-rag-router-update-20261021.zip -d zhaolu-ai-rag-router-update
```

### 3. 核对模型文件

```bash
ls -lh zhaolu-ai-rag-router-update/models/router/router.onnx
ls -lh zhaolu-ai-rag-router-update/models/embedding
```

### 4. 覆盖源码和模型

```bash
cp -rf /www/wwwroot/zhaolu-ai-rag-router-update/. /www/wwwroot/zhaolu-ai-v2/
```

覆盖后应确认：

```bash
test -f /www/wwwroot/zhaolu-ai-v2/models/router/router.onnx
test -f /www/wwwroot/zhaolu-ai-v2/models/embedding/CACHEDIR.TAG
```

### 5. 更新 `.env.baota`

至少增加：

```ini
RAG_VECTOR_ENABLED=true
RAG_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
RAG_EMBEDDING_CACHE_DIR=./models/embedding
RAG_EMBEDDING_TIMEOUT_SECONDS=20
RAG_VECTOR_WEIGHT=0.55
ROUTER_ML_ENABLED=true
ROUTER_ML_MODEL_PATH=./models/router/router.onnx
ROUTER_ML_TOKENIZER_PATH=./models/router/tokenizer.json
ROUTER_ML_LABEL_MAP_PATH=./models/router/label_map.json
ROUTER_ML_CONFIDENCE_THRESHOLD=0.5
```

### 6. 重新构建后端镜像

模型通过 Dockerfile 的 `COPY models ./models` 打入后端镜像，因此不能只重启容器。

```bash
cd /www/wwwroot/zhaolu-ai-v2
docker compose -p zhaolu-ai-v2 --env-file .env.baota -f docker-compose.baota.yml build --no-cache backend
docker compose -p zhaolu-ai-v2 --env-file .env.baota -f docker-compose.baota.yml up -d
```

`demo-init` 已放入 `demo` profile，普通 `up -d` 不会自动重复写入演示数据。仅在空数据库首次演示时使用 `--profile demo run --rm demo-init`。

### 7. 检查状态

```bash
docker compose -p zhaolu-ai-v2 --env-file .env.baota -f docker-compose.baota.yml ps
curl http://127.0.0.1:8000/api/v1/health
curl http://127.0.0.1:8000/api/v1/agent/capabilities
```

`capabilities` 中应能看到：

```text
rag_vector_enabled=true
router_ml_enabled=true
tool_count=17
```

### 8. 宝塔反向代理

宝塔站点反向代理仍指向 Nginx 或 `127.0.0.1:8000`，本次不修改前端界面和路由结构。

## 三、模型缓存与离线运行

后端镜像已设置：

```ini
HF_HUB_OFFLINE=1
```

因此服务不会在启动后尝试联网下载模型。

如果日志出现：

```text
Chinese vector RAG unavailable; falling back to lexical retrieval
```

说明向量模型未正确进入容器，但系统仍会回退关键词检索，不会导致主服务不可用。

## 四、2 核 4G 注意事项

`docker-compose.baota.yml` 已将后端容器内存上限从 600 MB 调整为 1100 MB。

估算总内存上限：

```text
MySQL 1200 MB
后端 1100 MB
Nginx 128 MB
合计约 2428 MB
```

这仍低于 4 GB，但必须注意：

- 不建议同时启动本地大模型。
- 不建议同时运行多个后端实例。
- 首次启动和向量首次查询会短时占用更多内存。
- 2 核 4G 的实际并发上限仍需服务器压测，不能只凭容器上限宣称通过。

## 五、回滚

保留更新前项目目录和数据库备份即可回滚：

```bash
docker compose -p zhaolu-ai-v2 --env-file .env.baota -f docker-compose.baota.yml down
mv /www/wwwroot/zhaolu-ai-v2 /www/wwwroot/zhaolu-ai-v2.failed
mv /www/wwwroot/zhaolu-ai-v2.backup /www/wwwroot/zhaolu-ai-v2
docker compose -p zhaolu-ai-v2 --env-file .env.baota -f docker-compose.baota.yml up -d
```

数据库回滚只在确认数据结构或业务数据确实受影响时执行，不能把回滚数据库当成常规操作。
