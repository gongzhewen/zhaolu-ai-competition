# 智能体反馈学习与轻量上下文

- 日期：2026-11-10
- 状态：代码、真实 MySQL 闭环和浏览器交互验证通过
- 边界：属于受控反馈学习，不改写模型权重

## 1. 轻量上下文

前端每次提问会附带最近 6 条对话，单条内容限制为 800 字符。

后端检测以下指代或省略表达：

- 他、她、该生、这个学生
- 该专业、上述省份
- 刚才、前述、其中、分别、同比
- “那……呢”类续问

当检测到续问时，将最近一轮用户问题与当前问题组合后再进入路由和工具规划，例如：

```text
分析2026年录取的王小明
继续追问：他的成绩是多少？
```

响应中返回：

- `original_question`
- `contextual_question`
- `context_resolution`

## 2. 认同与否定

每条 AI 回答均提供：

- 认同
- 否定

认同会进入原有反馈权重优化流程，并记录正向反馈。

否定会触发以下闭环：

1. 记录用户问题、原回答、意图、工具和否定原因。
2. 自动推断可能错误点：
   - 缺少工具证据
   - 可能误拒答
   - 年份或筛选条件丢失
   - 指标未完整覆盖
   - 数字或口径不一致
   - 意图识别错误
3. 将错误原因写入 `ai.agent_memory`，类型为 `reflection`。
4. 使用原问题再次执行受控工具链路，形成二次复核结果。
5. 只有二次结果同时满足以下条件才替换原结论：
   - 风险策略为 `answer`
   - 数据支撑充分
   - 数字证据支持
6. 否则明确提示“二次复核后仍缺少充分证据，建议人工核对”。

二次复核不会直接调用外部模型生成事实数字。

## 3. 反思记忆压缩

默认累计 4 条有效反思记忆后触发压缩，配置项：

```ini
AGENT_REFLECTION_COMPRESSION_THRESHOLD=4
```

压缩操作：

1. 汇总高频错误类型。
2. 生成高置信 `reflection_summary` 修正规则。
3. 将已压缩的细粒度反思记忆标记为过期。
4. 保留压缩摘要供后续问题使用。

压缩示例规则：

- 答案必须覆盖用户明确要求的全部核心指标。
- 复核年份、省份、专业和批次等条件是否保留。
- 回答数字必须与工具结果和统一口径一致。

## 4. 后续问题修正与检测

普通数据问答现在会加载用户长期记忆，而不只在本地模型规划时加载。

后续回答会依据压缩摘要检查：

- 是否存在工具证据
- 关键条件是否在证据筛选中保留
- 回答是否覆盖可核验指标
- 数字是否通过一致性检查

只有当反思摘要置信度不低于 0.8 且检测到明确冲突时，才触发保守阻断，避免单次反馈直接改变规则。

政策类、别名类、澄清和记忆指令不套用数据指标检查，避免误伤非数据回答。

## 5. 数据记录

错误原因写入：

```text
ai.agent_memory
```

反馈事件写入：

```text
ai.feedback
```

模板权重变化继续记录：

```text
ai.optimization_event
```

## 7. 限制

- 这不是神经网络参数微调，而是可审计的反馈记忆和规则修正。
- 单次否定只作为中等置信度信号，不应直接覆盖业务口径。
- 二次回答仍受原有权限、隐私、证据和风险门控约束。
- 反思记忆只对当前用户和学校范围生效。
- 后续仍需真实业务人员对错误原因和高频修正规则进行定期审核。
