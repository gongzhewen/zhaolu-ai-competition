# 国赛答辩技术证据

- 版本：ECSP-Admissions-G1
- 日期：2026-11-07

## 一、一句话定位

系统面向高校招生敏感结构化数据，将自然语言问题转换为可审计的受控查询，并通过歧义识别、数字证据、计划一致性、权限和风险门控决定“回答、澄清还是拒答”。

## 二、核心问题

评委可能追问：

> 这不就是通用 RAG 或 Text-to-SQL 加一个招生界面吗？

回答要点：

1. 招生问数的错误不只是一句 SQL 写错，还包括指标口径、年度范围、专业别名、权限和小样本隐私。
2. 通用 Text-to-SQL 把自然语言直接映射为 SQL，难以稳定表达“什么时候不该回答”。
3. G1 的重点不是让模型自由生成 SQL，而是把问题约束成受控槽位和 17 个受权工具。
4. 每个数字都有证据证书，回答通过数字核验后才能返回。
5. 学生名单、越权档案和小样本统计在执行工具前或结果返回前被硬门控。
6. 无本地模型时系统诚实走单计划快速路径，不把重复执行包装成双规划。

## 三、方法创新边界

可以使用：

> 面向招生敏感结构化数据，提出场景化的证据约束选择性问数方法，并以数字级证据证书、槽位歧义、权限门控和选择性计划核验构成完整闭环。

不建议使用：

- 全新通用算法
- 行业首创
- 大模型理论突破

原因：当前工作属于场景化算法与可信智能体工程创新，尚未形成新的通用学习理论。

## 四、为什么规则、工具和模型分层

| 层 | 作用 | 不让它做什么 |
|---|---|---|
| 规则 / ONNX | 识别意图、边界和关键槽位 | 不直接生成业务数字 |
| 本地模型 | 复杂问题候选规划、语言辅助 | 不绕过工具白名单 |
| 受控工具 | 从 MySQL 计算确定性结果 | 不返回未授权明细 |
| 证据校验 | 核对数字、来源和完整性 | 不放行无证据数字 |
| 风险门控 | 决定回答、澄清、无数据或拒答 | 不因为“想回答”而放宽隐私 |

## 五、如何证明不是错误回答

以“政治考了66分的人有多少”为例：

1. 路由识别为 `student_statistics`。
2. 槽位提取 `exam_subject_name=政治`、`exam_score_operator==`、`exam_score_value=66`。
3. 调用受控工具查询，不生成自由 SQL。
4. 返回人数、年度、科目和分数条件。
5. 回答数字必须能匹配工具指标或参数证据。
6. 若涉及可识别个体且样本小于 5，则抑制结果。

## 六、如何避免模糊回答

系统把模糊分成可解释类别：

- 指标歧义：招生人数、到校比例、招生规模。
- 实体歧义：这个专业、某位同名学生、张性同学。
- 缺少必填：计划增减数、学生姓名、年度。
- 权限歧义：普通账号查询学生档案。

高风险歧义优先输出具体澄清问题，而不是猜测用户意图。

## 七、为什么有第二计划

复杂或高风险问题可能需要不同工具组合。系统在本地模型可用时生成模型计划和规则计划，并规范化比较指标、表格和数据源。结果不一致则降低一致性分数并进入门控。

当前边界：

- 本地 MiniMind 未启用。
- 单计划快速路径是正常状态。
- 尚未在真实冻结集上证明双规划增益。

## 九、隐私与权限答辩

问题：为什么不直接给普通管理员查学生档案？

回答：

- 招生学生档案包含身份、联系方式、成绩和志愿等敏感信息。
- 权限不是界面隐藏，而是服务端和工具层双重校验。
- 普通分析只返回聚合分布。
- 小样本统计可能反推个体，需要抑制。
- 证据证书记录权限范围，审计可以追溯。

问题：如果把数据交给外部大模型，是否泄露？

回答：

- 系统不依赖外部大模型 API。
- 业务数字由本地 MySQL 和受控工具产生。
- BGE 向量模型、ONNX 路由模型和可选的 MiniMind 均设计为本地部署。
- 公开演示使用模拟数据。
